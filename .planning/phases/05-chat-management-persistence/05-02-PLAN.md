<task id="05-02-01" wave="1">
<title>Расширение ChatCompletionRequest и разработка методов сборки контекста и персистентности в ChatService</title>
<action>
1. В `backend/internal/model/llm.go`:
   - В структуру `ChatCompletionRequest` добавить поля:
     ```go
     ChatID  string `json:"chat_id,omitempty"`
     Content string `json:"content,omitempty"`
     ```
2. В `backend/internal/service/chat.go`:
   - Расширить интерфейс `ChatService`:
     ```go
     SaveUserMessage(ctx context.Context, chatID bson.ObjectID, userID int64, content string) (*model.Message, error)
     SaveAssistantMessage(ctx context.Context, chatID bson.ObjectID, userID int64, content string, usage model.TokenUsage) (*model.Message, error)
     AutoUpdateTitleIfNeeded(ctx context.Context, chatID bson.ObjectID, userID int64, content string) error
     PreparePromptContext(ctx context.Context, chatID bson.ObjectID, userID int64, newMsg string, maxHistory int) ([]model.ChatMessage, *model.Chat, error)
     ```
   - Реализовать `SaveUserMessage`: создает `model.Message` с `Role = "user"`, сохраняет через `messageRepo.Create`, вызывает `AutoUpdateTitleIfNeeded`, обновляет активность чата.
   - Реализовать `SaveAssistantMessage`: создает `model.Message` с `Role = "assistant"`, полями токенов и стоимости, сохраняет через `messageRepo.Create`.
   - Реализовать `AutoUpdateTitleIfNeeded`: проверяет заголовок чата. Если заголовок равен «Новый диалог», берет первые 45 рун текста пользователя, очищает пробелы, при длине > 45 добавляет `...` и вызывает `chatRepo.UpdateTitle`.
   - Реализовать `PreparePromptContext`: проверяет принадлежность чата `userID` (возвращает `model.ErrNotFound` для чужих). Извлекает последние `maxHistory` сообщений (по умолчанию 20) из MongoDB, разворачивает их в хронологический порядок (`ASC`), формирует срез `[]model.ChatMessage`, добавляет новое сообщение пользователя в конец среза и возвращает сформированный контекст и структуру `Chat`.
3. В `backend/internal/service/chat_test.go`:
   - Написать unit-тесты для `PreparePromptContext` (проверка скользящего окна 20 сообщений, хронологического порядка).
   - Написать тесты для `AutoUpdateTitleIfNeeded` (проверка обрезки до 45 рун, игнорирование, если заголовок уже кастомный).
   - Написать тесты для сохранения пользовательского и ассистентского сообщений.
</action>

<task id="05-02-02" wave="1">
<title>Интеграция сохранения сообщений и сборки контекста в StreamChat HTTP-хэндлер</title>
<action>
1. В `backend/internal/server/handler/chat.go`:
   - Обновить метод `StreamChat`:
     - Проверить наличие `req.ChatID`:
       - Если `req.ChatID != ""`:
         - Распарсить `bson.ObjectIDFromHex(req.ChatID)`. Если ошибка — вернуть HTTP 400 Bad Request.
         - Определить текст сообщения пользователя: если `req.Content != ""` использовать его; иначе если `len(req.Messages) > 0`, взять последнее `Messages[len-1].Content`.
         - Вызвать `chatSvc.PreparePromptContext(r.Context(), chatID, userID, userContent, 20)`:
           - При `model.ErrNotFound` вернуть HTTP 404 Not Found.
           - Подставить сформированный массив сообщений в `req.Messages`.
           - Если `req.Model == ""` и у чата указана модель, использовать `chat.Model`.
         - Сохранить реплику пользователя через `chatSvc.SaveUserMessage(r.Context(), chatID, userID, userContent)`.
         - Обновить активность чата и активную модель: `chatSvc.TouchChat(r.Context(), chatID, userID, req.Model)`.
     - При потоковой передаче накапливать сгенерированный текст ассистента в `generatedChars` / `strings.Builder`.
     - При наступлении события `StreamEventDone`:
       - Выполнить биллинг токенов через `billingSvc.ChargeTokens`.
       - Если `req.ChatID != ""`: сохранить ответ ассистента через `chatSvc.SaveAssistantMessage(r.Context(), chatID, userID, fullText, *lastUsage)` и вызвать `chatSvc.TouchChat`.
     - При обрыве соединения клиентом (`<-r.Context().Done()`):
       - В detached context с таймаутом (5 сек) списать накопленные токены.
       - Если `req.ChatID != ""` и было сгенерировано хотя бы одно слово/чанк, вызвать `chatSvc.SaveAssistantMessage(cleanupCtx, chatID, userID, fullText, *lastUsage)` и `chatSvc.TouchChat`.
2. В `backend/internal/server/handler/chat_test.go`:
   - Написать тесты на гибридный стриминг:
     - Запрос со `chat_id` вызывает сохранение в MongoDB и передачу контекста.
     - Запрос без `chat_id` работает в stateless-режиме Phase 4.
     - Запрос с чужим `chat_id` возвращает HTTP 404 Not Found без вызова LLM.
     - Разрыв клиентского соединения сохраняет частичный ответ и токены в detached context.
</action>
