# Phase 6: Next.js Frontend Interface - Context

**Gathered:** 2026-09-18  
**Status:** Ready for planning  

<domain>
## Phase Boundary

Полноценный адаптивный веб-интерфейс сервиса на Next.js (App Router, React 19, TypeScript, Tailwind CSS v4) для взаимодействия с LLM через бэкенд routerai.ru. Включает приветственный лендинг с авторизацией через VK OAuth / Dev Mock, боковую панель истории диалогов, окно чата с потоковым выводом ответов (SSE), подсветкой синтаксиса в блоках кода, селектором моделей, виджетом баланса в рублях с блокировкой ввода при нуле и модальным окном реферальной программы.
</domain>

## Requirements (locked via SPEC.md)

**6 requirements are locked.** See `06-SPEC.md` for full requirements, boundaries, and acceptance criteria.

Downstream agents MUST read `06-SPEC.md` before planning or implementing. Requirements are not duplicated here.

**In scope (from SPEC.md):**
- Приветственная посадочная страница (Landing) с кнопкой входа через VK ID и Dev Mock входом для разработки.
- Авторизационный контекст и защита маршрутов (редирект `/chat` ↔ `/` через серверный middleware и клиентский guard).
- Полнофункциональный сайдбар истории диалогов с адаптивным drawer для мобильных устройств.
- Окно сообщений с потоковым выводом SSE, автопрокруткой и кнопкой прерывания генерации.
- Markdown-парсер с подсветкой синтаксиса кода и кнопкой копирования блоков кода.
- Селектор доступных моделей routerai.ru с возможностью смены на лету.
- Виджет баланса в рублях с автоматическим обновлением после ответов модели.
- Экран/плашка блокировки при исчерпании баланса (HTTP 402) с приглашением в реферальную программу.
- Модальное окно реферальной программы с копированием ссылки и отображением начислений.

**Out of scope (from SPEC.md):**
- Подключение платёжных шлюзов (ЮKassa, Robokassa, СБП) — отложено до версии v2 (монетизация в v1 исключительно через приветственные 5 руб и реферальные 2 руб).
- Авторизация через Telegram, Google, email/пароль — в v1 строго VK OAuth.
- Загрузка вложений (изображений, PDF, файлов) — в v1 только текстовый чат.
- Голосовой ввод/вывод (Audio STT/TTS) — out of scope для v1.
- Редактирование и удаление отдельных сообщений внутри диалога — в v1 только удаление чата целиком.

<decisions>
## Implementation Decisions

### 1. Визуальная компоновка и дизайн-система (Sketch 001)
- **D-01:** За основу берется утвержденный макет **Sketch 001 (Вариант A: Classic Clean)**:
  - Левый сайдбар (260px) со списком чатов, кнопкой «Новый диалог» и профилем.
  - Верхний хедер: селектор моделей + интерактивный чип баланса в рублях (`5.00 ₽` с быстрой ссылкой на рефералов) + аватар.
  - Центрированная лента сообщений шириной 800px.
  - Плавающий нижний контейнер ввода с индикатором расчетной стоимости и кнопкой переключения «Отправить» / «Остановить генерацию».
  — **Reversibility:** costly — смена сетки layout затронет структуру страниц и стилизацию всех дочерних виджетов.
- **D-02:** Эстетика **Modern AI Dark** по токенам из `.planning/sketches/themes/default.css`:
  - Базовый фон `#090a0f`, панели `#0f1118`, карточки `#141724`, границы `rgba(255, 255, 255, 0.08)`.
  - Шрифты: `Inter` для UI, `JetBrains Mono` для кода и токенов.
  - Иконки: легковесный набор `lucide-react`.

### 2. Стейт-менеджмент и SSE-стриминг
- **D-03:** Клиентский SSE-стриминг реализуется через `fetch()` + `response.body.getReader()` (`ReadableStreamDefaultReader`) с ручным парсингом чанков `data: {...}\n\n` и поддержкой `AbortController`.
  — **Reversibility:** reversible — изолировано внутри хука `useChatStream`.
- **D-04:** Глобальный стейт чатов и сессий выносится в **Zustand** (`useChatStore`), что предотвращает лишние перерисовки сайдбара и шапки при быстром поступлении токенов в ленту.
  — **Reversibility:** costly — определяет структуру доступа к данным во всех компонентах интерфейса.
- **D-05:** Синхронизация баланса: при получении события `done` (`usage.cost_kopecks`) локальный баланс в сторе оптимистично уменьшается на списанную сумму, после чего выполняется фоновый `revalidate` профиля через `GET /api/v1/auth/me`.

### 3. Markdown и подсветка кода
- **D-06:** Для парсинга Markdown используется связка `react-markdown` (v9+) + `remark-gfm` (поддержка GFM-таблиц, списков, чекбоксов).
- **D-07:** Подсветка синтаксиса кода выполняется через `react-syntax-highlighter` (PrismJS, тема OneDark / vscDarkPlus). Каждый блок кода оборачивается в плашку с названием языка и кнопкой «Копировать код» со сменой иконки на галочку.
- **D-08:** Безопасность: плагин `rehype-raw` не подключается — рендеринг ведется строго через AST-дерево Markdown, что на 100% исключает внедрение вредоносного HTML/JS (XSS).

### 4. Маршрутизация и Auth Guard
- **D-09:** Серверная защита маршрутов в Next.js App Router через корневой `middleware.ts`:
  - Если запрос идет на `/chat` без HttpOnly cookie `auth_token` -> редирект на `/`.
  - Если авторизованный пользователь с кукой `auth_token` открывает `/` -> автоматический переход в `/chat`.
  — **Reversibility:** reversible — настраивается в конфигурации `middleware.ts`.
- **D-10:** Клиентский интерцептор сессии: при получении HTTP 401 Unauthorized от любого API-запроса клиент очищает локальное состояние и перенаправляет на `/`.
- **D-11:** Для локальной разработки (`process.env.NODE_ENV === 'development'`) на экране приветствия выводится кнопка «Быстрый вход (Dev Mock)», перенаправляющая на `/api/v1/auth/mock` без необходимости внешнего подключения к VK ID.

### 5. Дисциплина архитектуры (Правила MemPalace)
- **D-12:** Декомпозиция по стандартам проекта: файлы компонентов строго не более 200–250 строк. Сложные экраны разбиваются на субкомпоненты. Переиспользуемые примитивы выносятся в `src/components/ui/` или `src/shared/ui/`.

### Discretion агента
- Точный выбор CSS-анимаций для модального окна и выдвижного мобильного drawer.
- Детали форматирования времени сообщений (например, `14:32`).
- Организация внутренних типов данных в `src/types/chat.ts`.
</decisions>
