# Phase 3: Authentication & Referral System — Specification

**Created:** 2026-09-08
**Ambiguity score:** 0.08 (gate ≤ 0.20 passed)

## Goal

Реализовать полноценную систему аутентификации через VK OAuth 2.0, выпуск и валидацию JWT-сессий в защищённых HttpOnly cookies, выдачу профиля текущего пользователя и реферальную программу с атомарным начислением приветственного бонуса 5 руб (500 копеек) и вознаграждения рефереру 2 руб (200 копеек) в единой транзакции PostgreSQL.

## Background

В рамках Фазы 1 и Фазы 2 была подготовлена инфраструктура и слой данных (DAL):
- Таблицы `users`, `balances`, `balance_transactions`, `referrals` с ограничениями целостности.
- PostgreSQL репозитории `UserRepository`, `BalanceRepository` и транзакционный менеджер.
На текущий момент бэкенд имеет лишь тестовый эндпоинт `/health`. Для перехода к работе с чатами и инференсом routerai.ru (Фазы 4-5) требуется идентифицировать пользователя, сохранять сессию и гарантировать наличие баланса для тарификации.

## Requirements

### 1. AUTH-01: Аутентификация через VK OAuth 2.0
- **Current:** В `backend/internal/server` отсутствуют эндпоинты аутентификации.
- **Target:**
  - Реализовать OAuth 2.0 клиент для взаимодействия с VK API (`https://oauth.vk.com` и `https://api.vk.com/method/users.get`):
    - `GET /api/v1/auth/vk/login`: генерирует URL авторизации с параметрами `client_id`, `redirect_uri`, `response_type=code`, `scope=email` (опционально), `v=5.131` и случайным криптографическим `state` (в который упаковывается или связывается реферальный код `ref`), сохраняет `state` во временную cookie для защиты от CSRF и перенаправляет браузер на VK.
    - `GET /api/v1/auth/vk/callback`: принимает `code` и `state`, валидирует CSRF-state, обменивает `code` на `access_token` на сервере VK, запрашивает данные профиля пользователя (`id`, `first_name`, `last_name`, `photo_200`), извлекает реферальный код из `state`/cookie.
    - Поддержка тестового / dev-режима (Mock OAuth): при флаге `VK_MOCK_AUTH=true` или отсутствии боевых ключей в dev-окружении эндпоинт `/api/v1/auth/mock` позволяет моментально авторизоваться под тестовым пользователем для локальной разработки и сквозных тестов без реального обращения к VK.
- **Acceptance:** Успешный цикл редиректа на VK, обмена кода на токен и получения профиля пользователя, устойчивость к невалидным или истекшим кодам/state.

### 2. AUTH-02: Управление сессиями (JWT) и Auth Middleware
- **Current:** HTTP-сервер не проверяет авторизацию и не выпускает токены.
- **Target:**
  - Пакет `internal/auth/jwt`: генерация и валидация подписанных HMAC-SHA256 (HS256) JWT токенов с полями `sub` (user_id), `vk_id`, `iat`, `exp` (срок жизни по умолчанию 14-30 дней).
  - Установка сессии через защищённую cookie `auth_token` (`HttpOnly=true`, `SameSite=Lax`, `Path=/`, `Secure` при production-окружении).
  - Middleware `internal/server/middleware/auth.go`:
    - Проверяет cookie `auth_token` (или заголовок `Authorization: Bearer <token>` для гибкости API/тестов).
    - Валидирует подпись и срок действия токена, загружает `userID` в контекст запроса `r.Context()`.
    - Возвращает `401 Unauthorized` при отсутствии или невалидности токена.
  - Эндпоинты сессии:
    - `GET /api/v1/auth/me`: возвращает JSON с данными текущего пользователя (`id`, `vk_id`, `first_name`, `last_name`, `avatar_url`, `ref_code`, `ref_link`, `balance_rub`, `balance_kopecks`). Защищён Auth Middleware.
    - `POST /api/v1/auth/logout`: очищает cookie `auth_token` (Max-Age=0) и возвращает статус 200 OK.
- **Acceptance:** Защищённые эндпоинты возвращают 401 без токена; валидный токен в cookie открывает доступ к `/api/v1/auth/me`; `logout` инвалидирует сессию в браузере.

### 3. AUTH-03: Приветственный бонус (+5 руб / 500 копеек)
- **Current:** Метод `AddBonus` реализован в `BalanceRepository`, но логика первичной регистрации пользователя отсутствует.
- **Target:**
  - Если пользователя с полученным `vk_id` нет в таблице `users`, он создаётся в рамках транзакции PostgreSQL:
    - Генерируется уникальный `ref_code`.
    - Создаётся начальная запись баланса `amount_kopecks = 500`.
    - Создаётся проводка в `balance_transactions`: `amount_kopecks = 500`, `balance_after_kopecks = 500`, `type = 'welcome_bonus'`, `description = 'Приветственный бонус при регистрации'`.
  - Если пользователь уже существует — выполняется обновление данных профиля (`first_name`, `last_name`, `avatar_url`), но повторного начисления бонуса не происходит.
- **Acceptance:** При первой регистрации баланс нового пользователя равен 500 копейкам, в истории транзакций есть ровно одна запись типа `welcome_bonus`. При повторной авторизации того же пользователя баланс и транзакции не дублируются.

### 4. AUTH-04: Генерация уникальной реферальной ссылки
- **Current:** Поле `ref_code` есть в таблице `users`, но логика генерации и формирования ссылки отсутствует.
- **Target:**
  - Генератор криптографически надёжных случайных уникальных реферальных кодов (8-12 символов, base62/alphanumeric, без легко путаемых символов типа 0/O, 1/l).
  - Модель ответа `/api/v1/auth/me` включает вычисляемое поле `ref_link`, формируемое на основе базового URL приложения: `${FRONTEND_URL}/?ref=${ref_code}`.
- **Acceptance:** Каждый пользователь получает уникальный неизменный `ref_code`; поле `ref_link` формируется корректно с учетом конфигурации окружения `FRONTEND_URL`.

### 5. AUTH-05: Фиксация реферала и начисление вознаграждения (+2 руб / 200 копеек)
- **Current:** Таблица `referrals` создана в БД, репозиторные методы связи отсутствуют.
- **Target:**
  - При переходе по реферальной ссылке реферальный код передаётся в параметр `state` (или временную cookie `ref_code`).
  - При создании нового пользователя, если указан валидный `ref_code`:
    - Ищется пользователь-реферер по `ref_code`.
    - Проверка: нельзя стать рефералом самого себя (`referrer.ID != new_user.ID`).
    - Внутри той же транзакции, где создаётся новый пользователь и его приветственный бонус:
      1. Заполняется поле `users.referred_by = referrer.ID`.
      2. Добавляется запись в таблицу `referrals`: `referrer_id = referrer.ID`, `referee_id = new_user.ID`, `reward_kopecks = 200`.
      3. Рефереру начисляется +200 копеек через `balanceRepo.AddBonus`: запись в `balance_transactions` с типом `referral_reward`, описанием и ссылкой на ID нового пользователя.
  - Если `ref_code` не найден или невалиден — регистрация продолжается в штатном режиме без начисления реферального бонуса (fail-safe).
- **Acceptance:** При регистрации новичка по реферальному коду:
  - У новичка баланс = 500 копеек (welcome_bonus).
  - У пригласившего баланс увеличивается на 200 копеек, появляется проводка `referral_reward`.
  - В таблице `referrals` зафиксирована связка.
  - Повторное использование реферального кода тем же аккаунтом невозможно.

## Boundaries

**In scope:**
- Пакет `internal/auth`: VK OAuth клиент, генератор/валидатор JWT токенов, генератор `ref_code`.
- Сервисный слой `internal/service/auth` для координации транзакций регистрации, приветственного бонуса и реферального вознаграждения.
- Расширение репозитория пользователей/рефералов (`ReferralRepository` или методы в `UserRepository`).
- HTTP-эндпоинты:
  - `GET /api/v1/auth/vk/login`
  - `GET /api/v1/auth/vk/callback`
  - `GET /api/v1/auth/mock` (для dev/test окружения)
  - `GET /api/v1/auth/me`
  - `POST /api/v1/auth/logout`
- Middleware аутентификации `internal/server/middleware/auth.go`.
- Unit и интеграционные тесты авторизации, выдачи токенов и транзакционных начислений.

**Out of scope:**
- Логика взаимодействия с API routerai.ru (каталог моделей, генерация) — Фаза 4.
- Списание средств за токены LLM — Фаза 4.
- Хранение и менеджмент диалогов в MongoDB — Фаза 5.
- Next.js UI компоненты (кнопка входа, модалка рефералки) — Фаза 6.

## Constraints

- **Безопасность JWT**: Секретный ключ подписи `JWT_SECRET` (не менее 32 байт), валидация алгоритма (запрет `alg: none`), безопасные флаги cookie (`HttpOnly`, `SameSite=Lax`).
- **ACID-транзакции**: Создание пользователя, приветственного бонуса, фиксация реферала и начисление рефереру обязаны выполняться в одной транзакции PostgreSQL. При сбое транзакция откатывается целиком.
- **Денежные единицы**: Все расчеты и записи в БД ведутся строго в копейках (`BIGINT`):
  - Welcome bonus: 500 копеек (5.00 руб).
  - Referral reward: 200 копеек (2.00 руб).
- **Защита от CSRF**: Валидация криптографического `state` при OAuth callback.
- **Fail-safe для рефералов**: Некорректный или поддельный реферальный код не должен блокировать регистрацию пользователя.

## Acceptance Criteria

- [ ] `GET /api/v1/auth/vk/login` формирует корректный редирект на VK OAuth с защитой `state`.
- [ ] `GET /api/v1/auth/vk/callback` обменивает код, создаёт пользователя и устанавливает cookie `auth_token`.
- [ ] При первой регистрации на баланс пользователя начисляется 500 копеек (5 руб) с проводкой `welcome_bonus`.
- [ ] При переходе по реферальной ссылке реферер получает +200 копеек (2 руб) с проводкой `referral_reward`, а в таблице `referrals` создаётся запись.
- [ ] `GET /api/v1/auth/me` возвращает 401 без cookie, и 200 OK с валидным профилем и балансом при наличии сессии.
- [ ] `POST /api/v1/auth/logout` удаляет cookie и завершает сессию.
- [ ] Тестовый mock-режим (`VK_MOCK_AUTH=true`) позволяет проходить тесты без реального VK API.
- [ ] Конкурентные регистрации с одним и тем же VK ID корректно обрабатываются без дублирования балансов.
- [ ] `go test -v -race ./...` проходит успешно.
