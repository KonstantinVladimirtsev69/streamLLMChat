Вот типовой пример HTTP-хэндлера для Server-Sent Events в Go с использованием http.Flusher и контекста запроса:

go 
func StreamHandler(w http.ResponseWriter, r *http.Request) {
    flusher, ok := w.(http.Flusher)
    if !ok {
        http.Error(w, "Streaming unsupported", http.StatusInternalServerError)
        return
    }

    w.Header().Set("Content-Type", "text/event-stream")
    w.Header().Set("Cache-Control", "no-cache")
    w.Header().Set("Connection", "keep-alive")

    for i := 1; i <= 5; i++ {
        select {
        case <-r.Context().Done():
            // Клиент прервал соединение
            return
        default:
            fmt.Fprintf(w, "data: chunk %d\n\n", i)
            flusher.Flush()
            time.Sleep(200 * time.Millisecond)
        }
    }
}

В случае обрыва соединения клиентом вызов <-r.Context().Done() сработает мгновенно, предотвращая утечки горутин.

Ключевые преимущества SSE (Server-Sent Events) для LLM-чатов:

  • Однонаправленность: стриминг идет только от сервера клиенту, что идеально подходит под модель «один запрос — непрерывный поток токенов».
  • HTTP/2 совместимость: мультиплексирование соединений из коробки без накладных расходов на WebSocket handshake.
  • Встроенная поддержка авто-переподключения: стандарт браузерного EventSource автоматически восстанавливает соединение при микросбоях.
